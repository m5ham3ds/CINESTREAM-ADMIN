### 3. التحقق من سياسة إلغاء طلبات Pro المعدلة

#### أ. نص القاعدة المحدثة في `firestore.rules` (سطر 537-545):
```javascript
      allow update: if isAdmin() || (
        isAuthenticated() &&
        resource.data.userId == request.auth.uid &&
        request.resource.data.userId == request.auth.uid &&
        (resource.data.status == 'PENDING' || resource.data.status == 'pending') &&
        request.resource.data.status == 'CANCELLED' &&
        request.resource.data.diff(resource.data).affectedKeys().hasOnly(['status', 'updatedAt', 'cancelledAt'])

      allow delete: if isAdmin();
```

#### ب. نتائج الفحص الأمني في محاكي Firestore:
1. **السماح بالإلغاء لمالك الطلب المعلق بالحمولة الفعلية:** نجاح تحديث المستند مع `status: 'CANCELLED'`, `cancelledAt`, `updatedAt` (`assertSucceeds`).
2. **السماح بإلغاء طلب تاريخي بحالة `pending`:** نجاح تحديث الطلب التاريخي إلى `CANCELLED` بالحمولة الكاملة (`assertSucceeds`).
3. **منع الإلغاء لغير المالك:** فشل محاولة المستخدم B إلغاء طلب المستخدم A (`assertFails`).
4. **منع نقل الملكية:** فشل محاولة تغيير `userId` أثناء الإلغاء (`assertFails`).
5. **رفض الحالة الصغرى:** فشل محاولة الإلغاء باستخدام `status: 'cancelled'` (`assertFails`).
6. **رفض التهجئات غير المعيارية:** فشل محاولة الإلغاء باستخدام `status: 'CANCELED'` (`assertFails`).

9. **حظر إلغاء الحالات المعتمدة أو المرفوضة:** فشل إلغاء طلب بحالة `APPROVED` أو `REJECTED` (`assertFails`).
10. **منع إعادة فتح الحالات النهائية:** فشل نقل الحالة من `CANCELLED` إلى `PENDING` أو تعديل أي حقل بعد الإلغاء (`assertFails`).
